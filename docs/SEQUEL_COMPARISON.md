# Сравнение TBS1 / TBS2 / TBS3

## Гипотеза и предварительный результат

Проверяем гипотезу пользователя: продолжения могли исправить проблемы первой игры и дать подходящие образцы/ассеты для обратного переноса. По источникам она **частично подтверждается**: отдельные улучшения и исправления официально задокументированы. Универсальная гипотеза «третья часть уже решила UI» не подтверждена: рецензии TBS3 продолжают описывать перегрузку и перекрытия. Часть новшеств TBS2 официально перенесена в TBS1 ещё в 2016 году.

Источник-ID раскрыты в [UI_SOURCES.md](UI_SOURCES.md). Обе игры установлены пользователем; 19.10.2026 выполнен первый статический проход ниже. Игры для этого не запускались, сохранения не импортировались. Совместимость ресурсов и наблюдаемая работа экранов пока не установлены.

Практические выводы:

- В GuiToolTip всех трёх баз остаётся wordWrap=false. Перенос этого класса из продолжения сам по себе не решит длинную однострочную подсказку. Геометрия символов/внешние ограничения и другие типы подсказок этим не проверены.
- В четырёх различающихся классах экрана героя TBS3 видны выбор дополнительной способности, подтверждение/отмена, обучение этому выбору, сброс параметров и ветки Eternal Arena. Это конкретные зависимости от функций третьей игры, а не готовая универсальная переработка карточки TBS1. В GuiCharacterStats также виден clamp отрицательного отображаемого остатка очков к нулю; наличие такого дефекта в TBS1 не доказано.
- Исходный русский strings.json.z всех трёх игр читается существующим AMF3 Reader без изменения инструмента. Для TBS1 взята резервная копия до нашего патча, а не установленный кандидат. GUI TBS1/TBS2 содержит по 898 ключей: совпадают наборы ключей и 897 значений; единственное отличие — оформление mr_war_renown_clansmen_desc. В TBS3 1009 ключей: все 898 ключей первой сохранены, 897 общих значений совпадают, тот же один отличается; добавлено 111. Среди добавлений есть помощь Eternal Arena. Это сравнение только категории GUI, не способностей, диалогов или всей локализации.
- Исходное pg_q_stat_strength дословно одинаково во всех трёх базах. Более поздний номер игры не даёт готового исправленного пояснения силы.

SHA-256 русских strings.json.z: TBS1 f2e607c1a39377076913a4a04672139beaa514154499b9d024acccc07bfc3a96; TBS2 444ef1a2c2b5e9565e868a1f3c78b8d5fe680373340c34a8dd9488bb87ab7331; TBS3 f3f319dad30d5ada23529ea8270dbf57a3ae15f52a06020d62455909f343a63e. Извлечённые материалы остаются в игнорируемом local; в Git только выводы и идентичности.

Следующая гипотеза: значимые различия могут находиться в графических символах/раскладке и контекстном использовании общих классов. Проверить ресурсы и одинаковые действия в игре; не объявлять весь интерфейс одинаковым на основании десяти классов.

| Индикатор доступного повышения | D01 и E05 | Проверить реальные условия и обнаружимость в текущем ростере | Возможна уже существующая функция; не включать в обещания мода без пробела |

## Протокол прямого сравнения после установки

1. Записать storefront, application version, Steam build, locale и хеши исследуемых UI-ресурсов каждой игры. Использовать текущую TBS1 2.58.17 как базу, а не исторические скриншоты 2014 года.
2. Для одинаковых задач сравнить: обнаружить способность и её условия; выбрать закрытую фигурой цель; собрать отряд и понять роли; сменить предмет; понять ресурсы каравана; вернуться из окна/загрузить нужный профиль. Специфичные для продолжений механики исключать из одинакового сценария.
3. Снять наблюдаемое состояние, последовательность действий и исход. Отделить мышь от геймпада, EN от RU, обычную от плотной ситуации. Не сравнивать голый счёт кликов без одинаковой защиты от ошибочного подтверждения.
4. Для полезного отличия найти владельца: ресурс/символ/поле/событие/код, затем окончательный потребитель. Сравнить зависимости, шрифты, строковые токены, масштабы, жизненный цикл. Сходное имя класса не доказывает совместимость.
5. Зафиксировать результат как одно из: уже есть в TBS1; улучшено в продолжении и подходит; улучшено только для другой механики/устройства; проблема сохраняется; новый недостаток; не установлено. Только затем выбирать реализацию и делать макет.

Для первых сравнений не импортировать оригинальное прохождение пользователя в продолжения и не искать поздние сцены ценой спойлеров. Создавать отдельные тестовые профили, когда понадобится запись состояния, в рамках явной авторизации.

## Ассеты и способ поставки

Пользователь разрешил исследовать принадлежащие ему установки TBS2/TBS3. Это открывает статическое сравнение и локальные эксперименты. Выбор публично распространяемого payload остаётся отдельной проверкой условий и зависимостей.

Предпочтительный порядок: воспроизвести полезный принцип в исходных ресурсах TBS1; создать оригинальный необходимый элемент в её стиле; при реальной выгоде исследовать локальный перенос минимального ассета из собственной установки продолжения. Не копировать целиком SWF, набор шрифтов или экран до проверки зависимостей. Game-owned материал не включать в Git и не объявлять MPL.

По завершении сравнения выбрать конкретную функцию и проверить её механизм минимальной пробой. Один общий движок не является обещанием совместимости файлов, а наличие улучшения — доказательством желания разработчиков признать прежнее решение ошибкой. Их намерение отмечать только при прямом высказывании.
