# Рабочая среда разработки TBS1

**Принято 20.10.2026:** дальнейшие установки мода, рабочие запуски и runtime-испытания по умолчанию выполняются в отдельной DEV-копии. Личное прохождение запускается из Steam; его установка и хранилище не являются обычной целью следующих экспериментов. Это инфраструктура разработки, не новая функция распространяемого мода.

## Роли и запуск

| Объект | Назначение |
|---|---|
| Исходное дерево с проверенным оригиналом | Вход сборщика; не установленный модифицированный SWF |
| Неизменяемый кандидат мода | Версия, exact source и SHA-256 по CANDIDATES.md/TEST_BUILD_LOG.md |
| DEV-копия | Локальное сочетание кандидата и отдельной настройки запуска без Steam |
| Личная Steam-установка | Обычная игра пользователя; без новых рабочих установок по умолчанию |

Запускать DEV через основной ярлык «Banner Saga — разработка». Он проверяет хеши важных файлов и изоляцию хранилища, запрещает второй одновременный экземпляр игры, передаёт `steam=false locale=ru`. Steam можно оставлять открытым: запрет снят после контрольного совместного сеанса. Нужные каталоги, ярлык, `dev-support/dev-manifest.json`, резервные копии и свидетельства этой машины перечислены в игнорируемом `local/RESUME.md`. Их отсутствие в другом checkout не означает, что среда уже восстановлена.

DEV использует AIR application ID `TheBannerSagaDev`, отдельный от личной игры `TheBannerSaga`. В её Local Store один раз побайтово скопированы 11 сохранений обоих профилей и файл настроек. Это независимый снимок, без ссылок и дальнейшей синхронизации. Для испытаний продолжать использовать второй профиль. Сам запуск игры может перезаписывать свои настройки/master; автоматическое редактирование содержимого сохранений по-прежнему не разрешено. Журнал читать из хранилища DEV, не из старого журнала личной игры.

## Следующая сборка и установка

1. Восстановить текущую локальную конфигурацию по `local/RESUME.md`, проверить DEV-манифест, фактические хеши и процесс целевой игры. Не запускать/завершать игру автоматически ради восстановления контекста.
2. Собрать и заморозить кандидат мода из проверенного оригинального дерева по действующей процедуре. Номерной артефакт, его source/hash и прежние кандидаты не менять.
3. Отдельно подготовить DEV-вариант: сохранить/повторно применить проверенное разрешение `steam=false`, проверить точную входную базу и отсутствие неожиданных изменений SWF. Не копировать старое тело метода поверх новой неизвестной базы. Текущий опубликованный сборщик мода эту адаптацию автоматически не выполняет; локальные инструменты/свидетельства указаны в `local/RESUME.md`.
4. При закрытой целевой игре сохранить текущий DEV-payload и манифест вне загрузочного каталога, установить проверенный DEV-вариант и сверить хеш назначения. Зарегистрировать отдельно идентичность кандидата и хеш установленного составного файла. Только после этого обновить соответствующие поля `launch_file_hashes` в DEV-манифесте и выполнить `Launch-Dev.ps1 -CheckOnly` без запуска игры. Не подгонять манифест под необъяснённое изменение.
5. Пользователь выполняет нужный сценарий; агент снимает свежий DEV-журнал и сверяет исходное личное хранилище при проверке изоляции. Откат восстанавливает предыдущий проверенный DEV-payload и согласованный с ним манифест. Не использовать обычный исходный SWF как автоматический откат DEV: он уберёт настройку запуска без Steam.

Сборка возможна при открытой игре; замена установленного файла и откат — только при закрытой. Локальные дескриптор, конфигурация и ярлык сохраняются при обновлении кандидата. INI должен оставаться с переносами LF: ловушка CRLF и механизм обхода Steam описаны в [RESEARCH.md](RESEARCH.md#рабочая-копия-без-steam-и-изоляция-данных).

## Проверено и что остаётся открытым

Проверено на TBS1 Steam Windows application 2.58.17 / build 3268685: меню и штатный выход, отдельные физические файлы/журналы, отсутствие инициализации Steamworks и облачной синхронизации. В совместном сеансе около 231 с клиент Steam версии 1791918634 не отметил игру запущенной; локальные минутные счётчики, LastPlayed и журнал отслеживаемых процессов не изменились. Подробности и хеши свидетельств — [TEST_BUILD_LOG.md](TEST_BUILD_LOG.md#рабочая-среда-dev--20102026).

Это проверка конкретной конфигурации, без независимого запроса серверного счётчика Steam. После изменений Steam-интеграции, AIR/игровой базы, дескриптора или способа запуска повторять соответствующую проверку. Боевой сценарий и геймпад в DEV пока отдельно не испытаны; прежние результаты test.2 относятся к прежнему установленному файлу. Проверка DEV не заменяет требуемую перед выпуском проверку распространяемого кандидата в целевой Steam-среде.

Прямой вход в бой не настроен. Штатные `load`/`happening` найдены, но автономный корректный боевой сценарий не доказан; не превращать это в обязательное предварительное условие продолжения UI-мода. Игровые файлы, p-code, сохранения, приватные журналы и абсолютные машинные пути остаются вне Git.
