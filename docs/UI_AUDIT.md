# Предварительный аудит и реализуемость

Аудит — очередь проверок, не обещание реализовать всё. Приоритет определяется ущербом пониманию решения и доступностью узкой проверки, а не числом упоминаний. Оценки частоты у игроков нет.

## Выбор первого механизма

Цель — доказать безопасную управляемую правку объясняющего текста в реальном клиенте. Варианты: штатная локализация; экспорт контента Zeno; изменение программного SWF. Локализация использует уже подтверждённый потребитель, минимальна и обратима. Zeno пока не даёт доказанного преимущества для одной строки; SWF вносит лишние зависимости и риск обратной сборки. Для новых блоков интерфейса этот выбор нужно открыть заново.

## Gate первой пробы: READY для сборки и закрытой установки, runtime-unaccepted

- Изменяемое свойство: только русское пояснение силы, с явным следствием её потери; цветовой тег сохранён. Текст короче прежнего по символам, что не является доказательством отсутствия обрезания.
- Владелец: категория GUI, токен pg_q_stat_strength в локализации common/locale/ru/strings.json.z.
- Потребители/финальная запись: GuiBattleStatFlagTooltip.setContent → addContent → GuiToolTip.setContent; GuiPgTalents.updateStatTalentDisplay → _text_stat.htmlText → fixTextFieldFormat. Форматирование, переносы и реальные размеры проверяются в игре.
- Радиус: все потребители этого русского токена, в том числе боевые панели и доступный экран характеристик; при других локалях файл не используется. Нельзя обещать видимость всех экранов с первого часа прохождения.
- Инварианты: числа, расчёты, порядок ходов, способности, сохранения, другие строки/категории, прочие языки, SWF. Сборщик сравнивает весь разобранный объект с ожидаемым объектом, где изменён один ключ, и отклоняет побочные изменения ссылок AMF3.
- Приёмка: реальная загрузка, видимый текст и отсутствие обрезания; затем откат к исходному SHA-256 и повторная загрузка. Проверка Python не заменяет native readObject и экран игры.

## Макеты и продуктовые решения

Первый макет показывает только содержание пояснения, а не точный рендер Flash. Следующий разумный макет — компактная карточка способности: цель → эффект → стоимость → условие. Числа следует брать из текущего состояния клиента; примерные значения в макете не превращаются в собственный боевой калькулятор. До подтверждения механизма новые панели и перенос боевых органов управления не приняты.

Массовый редизайн, прогноз сюжетных последствий и спойлеры, возврат уже выполненных действий и ребаланс не входят в текущую реализацию. Если для информативности потребуется такое изменение, сначала обсудить его отдельно.
